# «Проверь ссылку»

Помощник, который проверяет подозрительное сообщение («ваша карта
заблокирована», «проголосуй за меня») и отвечает простыми словами:
**насколько это похоже на мошенничество (0–100) и почему**.

Готово: **этап 1 — ядро проверки** (`src/proverka`) и **этап 2 — Telegram-бот**
(`src/proverka_bot`, запуск и хостинг — см. [DEPLOY.md](DEPLOY.md)).
Дальше в плане: этап 3 — простой сайт.

## Как это работает

1. **Очистка текста.** Убираем невидимые символы, приводим «хитрые» буквы к
   обычным. Если в слове латинская «e» притворяется русской («Сбeрбанк»),
   это тоже признак обмана.
2. **Признаки в тексте.** Около 15 правил: просят код из СМС, пугают
   блокировкой, торопят, обещают выплату, просят перевести деньги на
   «безопасный счёт», «мама, это мой новый номер», просят установить
   программу и т.д.
3. **Проверка ссылок.** Ссылки **никогда не открываются**, проверяется только
   их текст: подделка известных сайтов (`sberbank-bonus.ru`, `sberbamk.ru`,
   `sberbаnk.ru` с русской «а»), IP-адрес вместо имени, трюк с `@`,
   короткие ссылки, дешёвые доменные зоны, ссылки на `.apk`.
4. **Оценка.** Каждый признак имеет вес. Веса объединяются формулой
   `риск = 1 − (1 − w1/100)·(1 − w2/100)·…`, поэтому оценка растёт с каждым
   признаком, но никогда не превышает 100.

| Оценка | Вывод |
|---|---|
| 0–19 | 🟢 Явных признаков нет (но это не гарантия) |
| 20–49 | 🟡 Есть подозрительные признаки |
| 50–79 | 🟠 Похоже на мошенничество |
| 80–100 | 🔴 Очень похоже на мошенничество |

## Запуск

Нужен Python 3.10+. Внешних зависимостей у ядра нет.

```bash
# проверить одно сообщение
cd src
python -m proverka "Ваша карта заблокирована! Срочно: sberbank-help.ru"

# запустить тесты
pip install pytest
cd ..
python -m pytest
```

### Бот в Telegram и MAX

```bash
cp .env.example .env          # вписать BOT_TOKEN и/или MAX_TOKEN
set -a && source .env && set +a
cd src
python -m proverka_bot poll   # Telegram (подробнее о вебхуке — DEPLOY.md)
python -m proverka_max        # MAX, в соседнем окне терминала
```

**MAX.** Та же логика проверки, что и в Telegram: адаптер `src/proverka_max` переводит события
MAX в общий формат, так что правила и тесты одни на оба мессенджера. Памятки открываются
inline-кнопками; бот принимает только свои известные кнопки, подделанные payload игнорируются.

**Новые возможности Telegram.** Пока бот читает скриншот, вместо лишнего сообщения
показывается анимированный черновик «Читаю картинку…» (`sendMessageDraft`), он исчезает сам,
когда приходит отчёт. Кнопка «SOS» в меню красная (стили кнопок, Bot API 9.4), в MAX тоже
(`intent: negative`). Старые клиенты эти поля просто игнорируют.

**Виджет-отчёт в Telegram (Bot API 10.4, по желанию).** С `TG_WIDGETS=1` отчёт приходит
интерактивной шкалой риска прямо в сообщении. Виджет не может слать запросы боту
(`allow_queries` выключен), строит интерфейс только через `textContent`, а в его состояние
попадают только оценка и причины, без текста проверяемого сообщения. Если виджеты недоступны
(старый клиент, групповой чат), бот сам отправляет обычный текстовый отчёт.

Круглосуточно на своём VPS (службы systemd с песочницей) — [`deploy/`](deploy/README.md).
На бесплатном хостинге через webhook — [DEPLOY.md](DEPLOY.md).

Из своего кода:

```python
from proverka import analyze, format_report

result = analyze("Ваша карта заблокирована! Срочно: sberbank-help.ru")
print(result.score)            # 0–100
print(format_report(result))   # объяснение простым языком
```

## Устройство кода

| Файл | Что делает |
|---|---|
| `src/proverka/extract.py` | находит ссылки и телефоны, удаляет невидимые символы |
| `src/proverka/text_rules.py` | правила-признаки мошенничества в тексте |
| `src/proverka/url_rules.py` | проверки ссылок |
| `src/proverka/analyzer.py` | собирает всё вместе, считает оценку, пишет отчёт |
| `src/proverka/data.py` | списки: официальные домены, сокращатели ссылок и т.п. |
| `src/proverka_bot/widget.py`, `widget_report.html` | виджет-отчёт для Telegram (Bot API 10.4) |
| `src/proverka_max/` | адаптер для мессенджера MAX |
| `tests/` | тесты (`python -m pytest`) |

## Безопасность и приватность

- **Ничего не сохраняется.** Текст сообщения живёт только в памяти на время
  проверки.
- **Ссылки не открываются** и в сеть программа не ходит (это проверяет тест
  `test_no_network`).
- **Защита от ReDoS.** Регулярные выражения простые, без вложенных повторений,
  текст ограничен 10 000 символами. Тесты подают «злой» ввод и проверяют, что
  ответ приходит быстро.
- **Адреса в отчёте «обезврежены»:** `sberbank-help[.]ru`, чтобы по ним нельзя
  было случайно нажать.
- **Отчёт — простой текст.** В нём есть куски чужого сообщения, поэтому бот
  должен отправлять его без `parse_mode` (HTML/Markdown), а сайт —
  экранировать (иначе возможна HTML-инъекция/XSS).
- **Секреты.** Токен бота хранится только в файле `.env` на месте запуска.
  Файл указан в `.gitignore` и в репозиторий не попадает.

## Ограничения (честно)

- Это **подсказка, а не гарантия**. Мошенники придумывают новые формулировки;
  низкая оценка не значит «безопасно».
- Правила подобраны вручную, а список официальных доменов неполный.
- «Зарегистрированный домен» определяется упрощённо (без полного Public
  Suffix List).
- Ядро работает полностью офлайн. Бот может дополнительно сверять **адреса
  ссылок** (без текста сообщения) с бесплатной базой URLhaus (abuse.ch),
  если задан `URLHAUS_KEY`. URLhaus в основном знает сайты, раздающие
  вирусы (.apk и т.п.), а не все фишинговые страницы, поэтому главными
  остаются правила.
